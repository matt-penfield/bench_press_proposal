### 3. 🔴 CRITICAL: Create AI Transparency Documentation

**What**: Document explaining model, licensing, and compliance  
**Where**: New file `docs/AI_TRANSPARENCY.md`  
**Time**: 15 minutes  
**Why**: Slalom policy requires documentation of T&Cs, model licensing, and data handling

**Create file** with this content:

```markdown
# AI Transparency & Licensing

## Model Used

**Name**: Xenova/all-MiniLM-L6-v2  
**Type**: Sentence Transformer (embedding model)  
**Size**: ~30 MB  
**Source**: https://huggingface.co/Xenova/all-MiniLM-L6-v2  
**License**: MIT License  

## What This Model Does

The model converts text into numerical vectors (embeddings) that capture semantic meaning.
Propel uses these embeddings to find proposals similar to your current opportunity.

**Example**:
- Your opportunity: "We need to modernize customer experience"
- Model converts to vector: [0.23, -0.45, 0.12, ...]
- Compares to all proposals in corpus to find similar vectors
- Returns ranked list of most-similar proposals

## Training Data

The model was pre-trained on CommonCrawl, Wikipedia, and other public sources.
**Important**: The model was NOT trained on any Slalom or client proprietary data.

## Commercial Use

MIT License permits unrestricted commercial use. Slalom may use this tool for:
- ✅ Internal proposal research
- ✅ Client delivery engagements
- ✅ Commercial proposals

No licensing fees or restrictions.

## Data Privacy

- Model runs entirely in your browser (WebAssembly)
- Your search queries and uploaded files NEVER leave your device
- Model weights are downloaded once from Hugging Face CDN (read-only, no tracking)
- No data is collected, logged, or used for model training
- Files are cleared when you close the page

## Security

- Open-source code (auditable)
- No dependencies on proprietary AI services
- No cloud API calls
- No training or fine-tuning of the model
- Input validation prevents injection attacks

## Compliance

- **GDPR**: No personal data processed or transmitted
- **HIPAA**: No healthcare data processing; suitable for general use only
- **SOX/PCI**: No payment/regulated data handled
- **Xenova License**: See https://github.com/xenova/transformers.js

## Q&A

**Is the AI model "trained" on my data?**  
No. The model was pre-trained by researchers at HuggingFace. Propel only uses 
the pre-trained model to convert your text to embeddings. No model training occurs.

**Can Slalom see my searches or uploaded files?**  
No. Everything happens on your device. Slalom cannot see your data unless you 
explicitly share the generated draft.

**Is this considered "Generative AI"?**  
Partially. The model generates embeddings (vectors), not text. However, Propel 
uses those embeddings to recommend proposals. The exported draft is assembled 
from existing proposal text (not LLM-generated), so it's lower-risk than ChatGPT.

**What if I upload confidential information by accident?**  
The data stays on your device and is cleared when you close the page. To be safe, 
don't upload confidential Slalom IP or client contracts. The tool is designed for 
publicly shareable opportunity/context information only.

**Where does the model get downloaded from?**  
Hugging Face CDN (https://huggingface.co/). This is a public, well-known source 
for open-source ML models. No private keys or APIs required.

## References

- Xenova/transformers.js: https://github.com/xenova/transformers.js
- Model Card: https://huggingface.co/Xenova/all-MiniLM-L6-v2
- Hugging Face Terms of Service: https://huggingface.co/terms-of-service
- MIT License: https://opensource.org/licenses/MIT

---

**Last Updated**: 2026-08-13  
**Compliance Status**: Aligns with Slalom AI Acceptable Use Policy v2.2
```

**What**: Document explaining how match quality is assessed  
**Where**: New file `docs/QUALITY_ASSURANCE.md`  
**Time**: 20 minutes  
**Why**: Slalom policy requires reviewed content; document quality process

**Create file** with this content:

```markdown
# Quality Assurance Process

## Matching Algorithm

The Propel tool ranks proposals using two factors:

1. **Semantic Similarity (78%)** — How similar the proposal content is to the opportunity
   - Uses cosine similarity of text embeddings
   - Scores 0–100 based on semantic closeness
   - Threshold: Results with <60% similarity are marked "Weak Match"

2. **Input Matching (22%)** — How well proposal metadata matches form inputs
   - Service area, industry, phase, deliverables, outcomes
   - Scores 0–100 based on field overlap
   - Ensures topical relevance beyond semantic similarity

**Final Score** = (Semantic × 0.78) + (Input × 0.22)

## Quality Thresholds

| Score | Label | Action |
|-------|-------|--------|
| 90–100 | Strong Match | High confidence; priority for review |
| 75–89 | Good Match | Solid relevance; recommended |
| 60–74 | Partial Match | Some relevance; review contextually |
| <60 | Weak Match | Low confidence; use caution or discard |

## Quality Assurance Checklist

Before using exported draft in client delivery:

**Content Review**:
- [ ] Read through generated proposal summary
- [ ] Verify all facts/claims are accurate
- [ ] Check that cited proposal details match source
- [ ] Ensure no outdated or irrelevant information

**Relevance Check**:
- [ ] Does the matched proposal actually address the opportunity?
- [ ] Are the use cases/outcomes applicable?
- [ ] Could any recommendations be misinterpreted?

**Bias/Fairness**:
- [ ] Does the matched proposal fairly represent the proposal corpus?
- [ ] Are diverse examples (company sizes, geographies, industries) represented?
- [ ] Are any recommendations reinforcing stereotypes or biases?

**Completeness**:
- [ ] Are key sections of the draft populated (no "TBD" or placeholders)?
- [ ] Do recommendations align with client's stated goals?
- [ ] Are timeline and team qualifications realistic?

**Compliance**:
- [ ] Is AI use disclosed in SOW and draft footer?
- [ ] Has client approved AI-assisted matching?
- [ ] Is attribution clear (source proposal IDs included)?

## Feedback & Continuous Improvement

Users can help improve matching by:
- Rating proposals: "Was this proposal useful?" (thumbs up/down)
- Flagging poor matches for review
- Suggesting missing proposal types

Future versions will track:
- Relevance metrics (% of top 3 proposals actually used)
- User satisfaction ratings
- Time savings vs. manual research
- Proposal corpus coverage gaps

---

**Last Updated**: 2026-08-13
```
